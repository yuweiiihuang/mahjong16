# Mahjong16 測試價值審查

用最小維護成本保護真實行為，不以測試數、覆蓋率或刪除行數作為成果。
概念來源：[OpenClaw test-audit](https://github.com/openclaw/openclaw/blob/main/.agents/skills/test-audit/SKILL.md)。
本版本以 Mahjong16 的規則引擎、WebTable、房間排程與 Qinghe Web UI 為責任邊界。

## 選擇範圍

- 新增或修改測試：套用下方四個問題，完成原任務。
- 審查或清理：先唯讀蒐證，再處理一組有共同責任邊界的候選。
- 全庫盤點：只有受要求時才展開，分區報告、分批修改；不自動重構正式程式。

先讀根目錄與涉及路徑的 AGENTS.md，遵循其中的 RTK 指令規則。
保留既有未提交修改；不能辨識的變更不重設、不納入清理。

## 新增測試前的四個問題

1. 保護哪個可觀察行為、不變量或獨立契約？
2. 哪個可信錯誤會讓它失敗？預期值須獨立於受測函式產生。
3. 現有測試為何抓不到？同一契約選最適合的主要邊界，另一層要有自己的風險。
4. 是否需要正式呼叫者用不到的 export、旗標、包裝或注入接口？若是，優先從真實邊界驗證。

未釐清時先找既有覆蓋或調整位置。優先擴充現有參數化案例與 fixture，
不新增平行框架或只服務測試的正式接口。
錯誤修正的回歸測試須在修正前因目標錯誤失敗、修正後通過；
用隔離暫存副本或安全還原局部修正驗證，不能破壞使用者工作樹。
無法驗證修正前失敗時明列缺口，不宣稱已證明回歸。

## 專案責任邊界

| 契約 | 優先位置 | 另一層值得測的不同風險 |
| --- | --- | --- |
| 合法動作、吃碰槓胡順序、死牆與回合轉移 | domain/；tests/env、tests/core | Web 動作傳遞、玩家視角、序列化 |
| 番數與計分明細 | domain/scoring；tests/scoring | 對外格式、規則設定傳遞 |
| 單機推進、快照、聽牌提示與偏好 | app/web.py 的 WebTable；tests/web 的 Python 測試 | 房間生命週期、排程與連線隔離 |
| 房間與同時反應 | app/web_rooms.py 的 WebRoom；tests/web 的 Python 測試 | HTTP 契約、權限、重試 |
| 按鈕、選牌、設定儲存與牌桌呈現 | ui/web/；tests/web/*.mjs | 瀏覽器 DOM、視窗尺寸、WebGL、非同步互動 |

以目前程式與呼叫鏈核實此表，不把路徑當成永久架構。
單機 advance 與房間 tick 有不同排程風險，不能因共用判斷函式就刪掉其中一路。
時序測試使用可前進的受控時鐘與正式路徑要求的鎖，不用真實等待掩蓋競態。
區分「牌型已聽」與「已宣告聽牌」、強制 PASS 與可選 PASS；
宣告聽牌後自動打進牌仍須保留可胡牌時的玩家選擇。

## 低價值候選與保留門檻

候選包括：無有效斷言、自我比較、照抄正式清單、用受測函式算預期值、
mock 自己實作被斷言的行為、重複同一契約、因無關 guard 通過的負向案例，
以及只為測試存在的正式接口或死碼。測試名稱與 fixture 也不能宣稱未實際涵蓋的行為。

原始碼字串比對、依函式名稱切割 JS 後用 vm 執行、私有方法或呼叫形狀斷言，
都是耦合候選，不是直接刪除理由。讀完整測試及正式呼叫鏈，辨識真實行為契約。
若改名或搬移就壞掉，優先把有價值的斷言移到穩定邊界；
不為此額外建立正式 export 或更換測試框架。

保留獨立的 API、資料格式、資訊隔離、設定、可觀察順序與可信回歸契約。
靜態檢查若是成本最低的獨立契約防線，且容忍無行為變更的改名，也可保留。
3D 幾何測試能驗證碰撞與座位轉換，不能證明畫面與操作正常；
瀏覽器 QA 也不能取代規則引擎回歸。慢、靜態或使用 mock 都不是單獨刪除依據。
基線失敗時先辨識產品、環境或測試問題，不直接刪除或改預期值。

## 清理前的證據

查完整測試、正式 owner、入口、呼叫者與被呼叫者、重疊測試、驗證入口及 git 歷史。
判斷依賴第三方行為時，讀實際使用版本的程式或型別。
每個刪除候選記錄：

- 測試名稱與位置、實際能抓到的錯誤。
- 正式程式及測試接口的非測試呼叫者。
- 留下的較強證據及位置，或契約已不需保護的原因。
- 建立原因與相關歷史；無法查明時列為不確定並保留。
- 可一併移除的無用接口或支援碼；沒有也可明列。
- 風險與最小驗證指令。

資料不足就保留。必要契約先搬移或補強，再刪舊測試；
證明沒有正式呼叫者後才刪測試專用接口，不留相容別名延續死碼。

## 驗證與交付

在根目錄啟用 .venv，依變更跑最小相關測試，再檢查共用邊界的其他呼叫路徑。
以下是工具例子，不要求每次全部執行：

```bash
source .venv/bin/activate
rtk pytest -q tests/web/test_ting_states.py
rtk proxy node --test tests/web/test_reaction_buttons.mjs
rtk git diff --check
```

跨層改動或清理完成後執行相關完整集合；發布前依 AGENTS.md 跑 Python 全套，
涉及前端則跑 Node 全套：

```bash
rtk pytest -q
rtk proxy node --test tests/web/*.mjs
```

不要在同一工作樹測試執行中修改受測檔案。
UI 行為或布局改動使用 `rtk python -m app.web --port 8000` 做本地瀏覽器檢查，
涵蓋相關桌面／窄視窗與擁擠牌桌；已有遊戲進行時另開測試埠，不重啟活躍服務。
純技能文件修改只需技能格式與 diff 檢查，不跑遊戲全套。

報告實際修正／刪除類型、保留候選原因、正式程式與測試各自的變更量，
以及實際跑過的檢查與缺口。一般新增測試只簡述保護行為與驗證結果。
提交、推送及 PR 遵循現有授權；UI 改動仍須讓使用者本地測試並明確批准推送。
